= triggers extension: AsciiDoc template

This template defines the **AsciiDoc binding** for the `triggers` extension (normative), followed by blocks to copy into an arc42 document.

**Prerequisite**: the document uses the `links` extension and its binding (see `links/EN/template.adoc`). Declare both:

[source,asciidoc]
----
Extensions used: links v0.1.0, triggers v0.1.0
----

== Notation

=== Identifiers and values

* In the tables of this binding, an element may be written as an xref (`+<<adr-007>>+`) or as a bare ID (`adr-007`).
* Event IDs start with `ev-` and revisit IDs with `rv-`. They are not elements of the `links` extension.
* A topic is written `topic:<name>`, such as `topic:messaging`. The `topic` prefix is reserved and is never an external URI.
* Dates are `YYYY-MM-DD`; durations are `PnYnMnWnD` with at least one part.

=== Subscriptions: local form

A description list with the role `[.triggers]`, placed in the subscriber's section. As in the `links` local form, the subscriber is the innermost enclosing section that has an element block anchor.

[source,asciidoc]
----
[[adr-007]]
=== ADR-007: Message broker selection

[.triggers]
baseline:: 2026-03-02
on time.elapsed:: every P3M
on stakeholder.changed::
on alternative.emerged:: due P60D, responsible <<sh-architect>>
----

* `baseline:: <date>`: the subscriber's baseline date. A decision that supersedes a subscriber but is not itself a subscriber may carry a `[.triggers]` block with only `baseline::`, to give the supersession an effective date (T16).
* `on <event type>:: <clauses>`: a subscription. An event type may appear at most once per subscriber (T1). The clauses are comma-separated, and none is required:
** `every <duration>` or `at <date>`: the parameter of `time.elapsed`.
** `due <duration>`: overrides the time allowed.
** `+responsible <<sh-…>>+`: overrides the responsible role.
** `+subject <<id>>+`: a subject filter.

=== Subscriptions: tabular form

A table with the role `[.triggers-subscriptions]`, for subscribers that are list items or table rows (such as §11 risks), or to document many subscribers at once. The first row is the header. The first two columns are `Subscriber` and `Baseline`; every other column is headed by an event type. An empty cell means no subscription; `yes` means a subscription with defaults; any other text holds clauses as in the local form.

[source,asciidoc]
----
[.triggers-subscriptions]
|===
|Subscriber |Baseline |time.elapsed |alternative.emerged

|<<risk-001>>
|2026-05-01
|every P6M
|

|<<adr-009>>
|2026-03-15
|every P12M
|yes
|===
----

=== Revisit Triggers subsection

Events, revisits, the topic map and custom event types live in tables in an additive subsection at the end of §9, titled `Revisit Triggers`. Each table's first row is its header, and the columns are fixed.

==== Events

Role `[.triggers-events]`, columns `ID | Date | Type | Subject | Payload | Published by`. The payload is `key: value` pairs separated by `;`. Publishing an event means appending a row.

==== Revisits

Role `[.triggers-revisits]`, columns `ID | Event | Subscriber | Scope | Responsible | Opened | Due | Outcome | Closed | Rationale`.

* `Scope` is `whole` or a comma-separated list of inputs.
* An empty `Outcome` means the revisit is open.
* The `Rationale` cell is free text. It also carries the closing fields `effect: unchanged|reopened`, `follows: <rv-id>` and `successor: <adr-id>`. These keys are reserved in the cell; write each at most once.

==== Topic map

Role `[.triggers-topics]`, columns `Topic | Elements`. The topic is its bare name (`messaging`); the elements are a comma-separated list.

==== Custom event types

Role `[.triggers-event-types]`, columns `Name | Mode | Subject kind | Routes | Payload | Default response`.

* `Mode` must be `published` in v0.1.
* `Routes` is a `;`-separated list of routes. A route is `self` or link types joined by `/`, then `->` and the scope: `self -> whole`, `addresses -> whole`, `uses-input/owned-by -> inputs`.
* `Payload` is a `;`-separated list of attribute names, each optionally followed by `: <description>`. An attribute is optional when its description ends with `(optional)`.
* `Default response` is `+responsible: owner|subject|<<sh-…>>; due: <duration>+`.

=== §11 Risk with periodic re-assessment

A §11 risk written as a list item uses the tabular forms:

[source,asciidoc]
----
* [[risk-003]]**Third-party API rate limits**: ...

[.links]
|===
|Source |owned-by

|<<risk-003>> |<<sh-ops>>
|===

[.triggers-subscriptions]
|===
|Subscriber |Baseline |time.elapsed

|<<risk-003>> |2026-05-01 |every P6M
|===
----

=== §11 Overdue revisit as a risk

When a revisit is overdue, it SHOULD appear in §11:

[source,asciidoc]
----
* [[risk-004]]**Overdue revisit rv-004 on ADR-007**: the `alternative.emerged` event ev-003 claimed NATS covers asynchronous messaging. The revisit was due 2026-10-03 and is still open.
  Mitigation: escalate to the architecture review board, or close rv-004.
----

=== Publishing an event

Append a row to the Events table. Then apply the manual procedure of the SPEC (by hand, or with a conforming tool) to find the revisits to open.

=== Closing a revisit

Fill in the revisit row's `Outcome`, `Closed` and `Rationale`. For `amended` with inputs scope, add `effect: unchanged` or `effect: reopened` to the Rationale cell. With `effect: reopened`, add the follow-on whole-scope revisit and put `follows: <rv-id>` in its Rationale cell. For `superseded`, add `successor: <adr-id>`.
